# 风险评估矩阵

## 风险等级定义

| 等级 | 定义 | 应对策略 |
|------|------|----------|
| **高** | 可能导致资金损失、数据不一致、服务不可用 | 必须有回滚方案，需要审批 |
| **中** | 可能影响用户体验、性能下降、部分功能异常 | 需要测试验证，建议灰度发布 |
| **低** | 影响范围小、可快速修复、不影响核心功能 | 正常测试流程 |

## 风险类型详解

### 1. 数据一致性风险

**高风险场景**：
- 涉及数据库 schema 变更（ALTER TABLE）
- 跨表数据迁移
- 修改核心业务数据的写入逻辑
- 涉及分布式事务

**检查项**：

| 检查项 | 高风险标志 |
|--------|-----------|
| 数据库 schema 变更 | 添加/删除/修改列、索引变更 |
| 数据迁移 | 需要回填历史数据 |
| 事务边界变更 | 修改 @Transactional 范围 |
| 幂等性 | 重复执行会产生不同结果 |

**应对措施**：
- 准备数据回滚脚本
- 分步执行：先加列→迁移数据→再删旧列
- 使用 Online DDL 减少锁表时间
- 验证数据一致性的检查脚本

### 2. 兼容性风险

**高风险场景**：
- 修改对外 API 的入参/出参
- 删除或重命名 API 端点
- 修改消息格式（MQ、RPC）
- 配置项变更

**检查项**：

| 检查项 | 高风险标志 |
|--------|-----------|
| API 变更 | 删除字段、修改类型、更改语义 |
| 版本控制 | 没有版本号管理 |
| 下游影响 | 有外部系统依赖 |
| 配置兼容 | 需要同步更新配置 |

**应对措施**：
- API 版本控制（v1 → v2）
- 过渡期保留旧接口
- 提前通知下游系统
- 使用 Feature Flag 控制

### 3. 性能风险

**高风险场景**：
- 修改高频调用路径（QPS > 1000）
- 增加数据库查询
- 增加外部服务调用
- 修改缓存策略

**检查项**：

| 检查项 | 高风险标志 |
|--------|-----------|
| 调用频率 | 涉及高 QPS 接口 |
| 数据库 | 新增查询、修改索引 |
| 外部调用 | 新增 HTTP/RPC 调用 |
| 缓存 | 删除缓存、修改缓存策略 |
| 批量处理 | 循环中的数据库/网络操作 |

**应对措施**：
- 性能基准测试
- 慢 SQL 分析
- 限流降级预案
- 缓存预热方案

### 4. 并发风险

**高风险场景**：
- 涉及共享状态修改
- 分布式锁变更
- 事务隔离级别变更
- 异步转同步或反之

**检查项**：

| 检查项 | 高风险标志 |
|--------|-----------|
| 共享状态 | 修改全局变量、缓存、数据库 |
| 锁机制 | 分布式锁、数据库锁 |
| 竞态条件 | 读-改-写操作 |
| 死锁 | 多资源锁定 |

**应对措施**：
- 使用分布式锁（Redisson）
- 乐观锁（版本号）
- 幂等性设计
- 并发测试

### 5. 安全风险

**高风险场景**：
- 涉及权限控制变更
- 处理敏感数据（密码、手机号、身份证）
- 修改加密/脱敏逻辑
- 审计日志变更

**检查项**：

| 检查项 | 高风险标志 |
|--------|-----------|
| 权限 | 修改鉴权逻辑 |
| 敏感数据 | 处理 PII 数据 |
| 加密 | 修改加密算法或密钥 |
| 审计 | 变更审计日志记录 |

**应对措施**：
- 安全审查
- 数据脱敏验证
- 权限矩阵更新
- 审计日志完整性检查

1. **代码回滚**
   ```bash

   # 或
   kubectl rollout undo deployment/[deployment_name]
   ```

2. **配置回滚**
   [配置回滚步骤]

3. **数据回滚**（如需要）
   ```sql
   -- 回滚 SQL
   ```

### 回滚验证

- [ ] 服务正常启动
