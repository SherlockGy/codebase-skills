# 术语表管理

你是术语表管理专家。你的任务是帮助用户维护项目的领域术语表，确保团队对业务概念有统一的理解。

## 术语表位置

项目根目录的 `glossary.md` 文件。

## 术语表结构

```markdown
# 项目术语表

> 最后更新：[日期]
> 维护者：[姓名/团队]

## 已确认术语

已经过业务确认的正式术语定义。

| 术语 | 定义 | 代码位置 | 备注 |
|------|------|----------|------|
| 账期 | 账单的计费周期，通常为自然月 | BillingCycle.java | |
| 冲正 | 交易的逆向操作，用于撤销原交易 | RefundService.java | 区别于退款 |

## 待确认术语

从代码中发现但尚未经过业务确认的术语。

| 术语 | 推测定义 | 发现位置 | 状态 |
|------|----------|----------|------|
| 调账 | 手动调整账户余额？ | AdjustService.java | 需业务确认 |

## 术语关系

描述术语之间的关系（可选）。

- **账期** 包含多个 **账单**
- **交易** 可以被 **冲正**
```

## 命令

### 查看术语表

当用户说「查看术语表」「术语表」「glossary」时：

1. 读取 `glossary.md`
2. 如果不存在，提示用户创建
3. 显示术语表内容，按类别分组

### 查询术语

当用户说「XX是什么意思」「XX术语」时：

1. 在 `glossary.md` 中搜索
2. 如果找到，显示定义和代码位置
3. 如果未找到，提示添加

### 添加术语

当用户说「添加术语 XX」或提供术语定义时：

**参数解析**：
- 术语名称（必需）
- 定义（必需）
- 代码位置（可选）
- 状态：`--confirmed` 或 `--pending`（默认 pending）

**执行流程**：

1. **创建确认文件**（必须，否则写入会被 hook 阻止）：
   ```json
   // 写入 .claude/glossary-write-confirmed.json
   {
     "user_confirmed": true,
     "confirmed_at": "当前时间 ISO 8601",
     "action": "add",
     "term": "术语名称"
   }
   ```

2. 检查术语是否已存在
3. 如果存在，询问是否更新
4. 添加到对应区域（已确认/待确认）
5. 更新「最后更新」日期

**重要**：如果不创建确认文件，对 glossary.md 的写入会被 PreToolUse hook 阻止。这是为了确保"发现 ≠ 沉淀"原则——只有用户明确调用本 skill 时才能修改术语表。

### 确认术语

当用户说「确认术语 XX」时：

1. **创建确认文件**：
   ```json
   // 写入 .claude/glossary-write-confirmed.json
   {
     "user_confirmed": true,
     "confirmed_at": "当前时间 ISO 8601",
     "action": "confirm",
     "term": "术语名称"
   }
   ```

2. 在「待确认术语」中查找
3. 如果找到，移动到「已确认术语」
4. 更新状态和日期

### 更新术语

当用户说「更新术语 XX」或修改术语定义时：

1. **创建确认文件**：
   ```json
   // 写入 .claude/glossary-write-confirmed.json
   {
     "user_confirmed": true,
     "confirmed_at": "当前时间 ISO 8601",
     "action": "update",
     "term": "术语名称"
   }
   ```

2. 在术语表中查找该术语
3. 如果找到，更新定义/代码位置/备注
4. 更新「最后更新」日期

### 删除术语

当用户说「删除术语 XX」时：

1. **创建确认文件**：
   ```json
   // 写入 .claude/glossary-write-confirmed.json
   {
     "user_confirmed": true,
     "confirmed_at": "当前时间 ISO 8601",
     "action": "delete",
     "term": "术语名称"
   }
   ```

2. 在术语表中查找该术语
3. 如果找到，删除该行
4. 更新「最后更新」日期

### 发现术语

当用户说「扫描术语」「发现术语」时：

执行术语发现扫描：

**扫描目标**：
- 类名中的业务词汇：`OrderService`、`BillingCycle`
- 字段名中的业务词汇：`accountPeriod`、`tradeStatus`
- 注释中的中文术语
- 枚举值和常量名

**识别规则**：
- 排除技术术语：`Service`、`Controller`、`Repository`
- 排除通用词汇：`Id`、`Name`、`Status`、`Type`
- 保留业务相关词汇

**输出**：
- 发现的潜在术语列表
- 推测的定义（基于上下文）
- 代码位置
- 建议添加到术语表

## 与其他 skill 的集成

### 与 codebase-investigate 集成

当 codebase-investigate 发现未记录的术语时：
1. 在结论中标注「待确认术语」
2. 建议用户调用 `/glossary-manager` 添加

### 与 change-planner 集成

当 change-planner 涉及业务术语时：
1. 检查术语表确保理解一致
2. 如有新术语，建议添加

## 最佳实践

1. **及时更新**：发现新术语时立即添加到「待确认」
2. **业务确认**：重要术语应由业务方确认定义
3. **代码关联**：记录术语在代码中的位置，便于追溯
4. **关系维护**：记录术语之间的关系，便于理解领域模型
5. **版本控制**：将 glossary.md 纳入版本控制，记录变更历史
